================================================================================
  DCRS — Digital Citizen Response System
  How to Run (Local Development)
================================================================================

PREREQUISITES
-------------
  - Python 3.10 or later
  - pip (Python package manager)
  - Git

  Optional (for production-style database):
  - PostgreSQL

  The project works out of the box with SQLite (no setup needed).


STEP 1 — CLONE THE REPO (skip if already cloned)
--------------------------------------------------
  git clone https://github.com/troubleman96/DCRS---DIGITAL-CITIZEN-REGISTRATION-AND-SMS-BASED-SYSTEM.git
  cd DCRS---DIGITAL-CITIZEN-REGISTRATION-AND-SMS-BASED-SYSTEM


STEP 2 — CREATE A VIRTUAL ENVIRONMENT
---------------------------------------
  python3 -m venv venv
  source venv/bin/activate        # Linux / macOS
  # venv\Scripts\activate         # Windows


STEP 3 — INSTALL DEPENDENCIES
-------------------------------
  pip install -r requirements/base.txt

  This installs:
    - Django 5.x
    - Pillow (image handling for citizen profile photos)
    - python-dotenv (loads .env file)
    - requests (HTTP client for SendAfrica SMS API)


STEP 4 — CONFIGURE ENVIRONMENT VARIABLES
------------------------------------------
  Copy the example env file and edit it:

    cp .env.example .env

  For local development with SQLite, the minimal .env is:

    SECRET_KEY=dev-secret-key-change-in-production
    DEBUG=True
    ALLOWED_HOSTS=localhost,127.0.0.1

  Everything else has sensible defaults. Leave SENDAFRICA_API_KEY blank
  to use the built-in SMS simulator (no real SMS sent).


STEP 5 — RUN DATABASE MIGRATIONS
-----------------------------------
  python manage.py migrate

  This creates the SQLite database (db.sqlite3) and all tables.


STEP 6 — SEED DEMO DATA (optional but recommended)
-----------------------------------------------------
  python manage.py seed

  Or:

    python seed.py

  This populates the database with demo regions, districts, wards, mitaa,
  sample citizens, issues, and an admin user so you can explore the system
  immediately.


STEP 7 — CREATE A SUPERUSER (optional)
----------------------------------------
  python manage.py createsuperuser

  Follow the prompts. You can also log in with the seeded admin account
  if you ran the seed command.


STEP 8 — START THE DEVELOPMENT SERVER
----------------------------------------
  python manage.py runserver

  The server starts at: http://127.0.0.1:8000

  Open that URL in your browser.


DEFAULT LOGIN (if seeded)
--------------------------
  Admin:      admin / admin123
  Officers:   officer_1 / officer123, officer_2 / officer123, etc.
  Citizens:   Use the registration form at /register/

  You can also sign in with the phone number instead of username.


PROJECT URLS
-------------
  /                       Public landing page (stats + live issue feed)
  /admin/                 Django admin panel
  /login/                 Officer / admin login
  /register/              Citizen self-registration
  /citizens/              Citizen management (staff only)
  /issues/                Issue tracking (staff only)
  /portal/                Citizen portal (after login as citizen)
  /sms/compose/           Send a one-off SMS (staff only)
  /sms/broadcast/         Broadcast SMS to a ward (staff only)
  /sms/log/               Full SMS delivery history (staff only)
  /reports/               Registration reports and dashboard (staff only)
  /audit/                 Audit trail (staff only)


SMS GATEWAY
------------
  By default, SMS messages are handled by the built-in simulator.
  No real SMS is sent — messages are just logged in the SMS Log.

  To send real SMS via SendAfrica:
  1. Sign up at https://sendafrica.online
  2. Get your API key from Settings -> API Keys
  3. Add it to your .env:
       SENDAFRICA_API_KEY=your-actual-api-key
       SENDAFRICA_SENDER_ID=YourSender
  4. In the SendAfrica dashboard, set the delivery report callback URL to:
       https://your-domain.com/portal/sms/callback/


TROUBLESHOOTING
----------------
  Q: "No module named dotenv"
     A: Run: pip install python-dotenv

  Q: CSRF 403 errors on forms
     A: Make sure DEBUG=True in .env for local dev.
        For production behind HTTPS, set CSRF_TRUSTED_ORIGINS properly.

  Q: Database errors
     A: Re-run migrations: python manage.py migrate
        Or delete db.sqlite3 and migrate fresh.

  Q: Static files not loading
     A: Run: python manage.py collectstatic
        (Not needed in DEBUG mode — Django serves them automatically.)

  Q: Forgot admin password
     A: python manage.py shell
        >>> from apps.accounts.models import User
        >>> u = User.objects.get(username='admin')
        >>> u.set_password('newpassword')
        >>> u.save()
